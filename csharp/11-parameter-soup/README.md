# Kata 11: Parameter Soup

## Business Scenario

This kata is about a travel booking engine. The implementation works and the tests describe the current behavior, but the code is intentionally awkward so it can be improved through refactoring.

## Component Usage

The component prices and confirms a trip using many separate booking inputs. Treat the tests as the contract while you improve the internal design.

## How to Run

```bash
make test
```
